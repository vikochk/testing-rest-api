# v.kochneva. REST API. JSONPlaceholder.

API автотесты для сервиса https://jsonplaceholder.typicode.com/ на Python с использованием requests, PyTest и Pydantic для валидации моделей данных.

---

## Как запустить проект
1. Клонировать репозиторий:

```bash
git clone https://github.com/vikochk/testing-rest-api.git
cd <project_folder>
```

2. Установить Python 3.11+.

Если используется pyenv:

```bash
pyenv install
```

3. Создать виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate    # Linux/macOS
.venv\Scripts\activate.bat   # Windows
```

4. Установить зависимости:

```bash
pip install -r requirements.txt
```

5. Проверить конфигурацию тестовых данных в папке `tests/resources/`

Внутри папки находятся файлы `posts_data.json` и `users_data.json`. В них можно изменять ожидаемые параметры (ID, ожидаемые статус-коды, эталонные профили пользователей) для проведения проверок.

6. Запустить тесты:
- Запуск всех тестов: `pytest`
- Запуск конкретного файла: `pytest tests/test_api.py`

### Реализованные тесты
## Комплексная проверка REST API сервиса JSONPlaceholder
Проверяет сквозной сценарий взаимодействия с сущностями публикаций (posts) и пользователей (users) в рамках одного тестового сценария:

- **Шаг 1.** Получение списка всех публикаций: проверка успешности запроса, валидация структуры списка публикаций через модель PostModel и проверка сортировки публикаций по возрастанию поля id.
- **Шаг 2.** Запрос конкретной публикации по ID: получение публикации, проверка корректности возвращенных данных (соответствие userId и id ожидаемым параметрам) и валидация на непустые поля title и body.
- **Шаг 3.** Запрос несуществующей публикации: отправка запроса на получение публикации, проверка кода ответа и подтверждение того, что тело ответа вернулось пустым.
- **Шаг 4.** Создание новой публикации: отправка POST-запроса на создание записи с использованием случайно сгенерированного контента для полей title и body, проверка успешности создания (код 201) и валидация сохраненных данных на сервере.
- **Шаг 5.** Получение списка всех пользователей: запрос списка пользователей, поиск конкретного пользователя по ID и полное сравнение структуры и значений его профиля с ожидаемыми эталонными данными из ресурсов.
- **Шаг 6.** Запрос пользователя по ID: точечный запрос профиля пользователя, валидация структуры ответа через модель UserModel и сверка всех вложенных полей.
